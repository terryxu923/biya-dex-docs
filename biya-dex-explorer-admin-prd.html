1. 本版交付摘要

1.1 产品目标

BiyaDEX 区块浏览器直接向自有节点取数。页面上的高度就是该节点当时承认的执行高度。值班需要回答三件事：问得到节点吗、节点还在往前走吗、问回来的高度是否连续且内容完整。

没有本后台时，异常只出现在前台失败或群消息里，无法留下可核对的证据、备注、人工结案和通知结果。本版解决「能看见、能备注、能处理结案、能确认是否已通知」，不解决「在后台把节点修好」。

数据前提： 不存在「查询库落后于这台节点」这一层，也不为此单开告警。

目标与非目标

目标 可观察结果
值班可判断 总览给出连通、进度、高度连续性之一的主结论，以及告警中条数
告警可核对 仅 3 类目录可打开详情；证据快照为告警当时字段，足够判断类型
沟通可留痕 备注出现在告警时间线；新开告警有一条 Lark 产生记录
状态可结案 系统只写入「告警中」；值班可将告警中处理为「已处理」，不可改回；巡检不自动改状态
事实只读 后台没有任何改高度、改交易的按钮

非目标： 节点修复、回补/重放、独立查询菜单、操作记录页、登录页、角色与权限配置、交易运营、EVM/Token/合约、告警关联交易。

1.2 V1.0 功能清单

本期验收以此表为准。侧栏只有 1、2；3 挂在告警上，不单独成菜单；4 为顶栏附属，不单独成菜单。

序号 模块 功能说明
1 运行总览 作为 Explorer 后台落地页，只读展示自有节点：最新高度、共识轮次、最新区块时间、待处理告警条数；按连通 → 进度 → 连续性给出一条主结论（节点不可达 / 不前进 / 区块缺口 / 自有节点正常）；观察与前台同一窗口的总交易数、24h 链上交易、地址总数、24h 活跃地址，以及节点连通 / 区块查询两行耗时；「需要关注」只列告警中、最多 5 条。不配 TPS、不改高度或阈值、不把节点观测改成正常，首页统计不单独告警
2 告警中心 值班查看与结案台：目录仅节点不可达、节点不前进、区块缺口三类；列表按类别 / 状态筛选，默认最近发生降序、每页 10 条；详情只读告警当时快照，每条最多 1 条备注（≥3 字）、将告警中处理为已处理且不可改回。巡检不自动结案、无「已恢复」、无分派 / 补齐 / 重处理、无查看关联数据、不打开交易或地址
3 Lark 通知 仅新开「告警中」按三类模板向 BIYA-DEX Explorer 告警 发一条「产生」；列表与详情记录已通知 / 通知失败。去重只更新最近发生、备注、处理、巡检条件消失都不发、不写恢复消息；失败不改告警状态，后台不重发
4 区块核对 顶栏按区块高度 / 区块哈希打开只读抽屉（区块概览 / 数据来源），供核对某一高度是否可查询或为缺口。概览仅高度、查询状态、哈希、区块时间；数据来源仅来源与查询状态。无侧栏查询菜单，无父哈希 / 提议者 / 链上交易数，无块内交易、无交易 / 地址抽屉、无前后翻页，不作为告警结案路径

1.3 核心数据模型

层级 实体 标识 对应 1.2 人工可改
L1 节点观测 自有节点 1 运行总览 不可改
L2 告警 告警编号 2 告警中心 每条最多写 1 条备注；将告警中处理为已处理
L2 Lark 记录 告警子记录 3 Lark 通知 系统写
L3 区块 高度 / 区块哈希 4 区块核对 不可改

生效原则

  • 巡检： 系统按连通 → 进度 → 连续性的顺序，向自有节点做的一轮检查。
  • 巡检只创建「告警中」，不写入「已恢复」，不因当前三项均通过而自动结案。
  • 值班把「告警中」处理为「已处理」后，该条不再计入待处理；不可改回告警中。
  • 协议执行拒绝、未登记交易类型：前台照常展示，不进告警目录。本期告警不关联具体交易。

1.4 本版不做

不在 1.2 四项之内的能力本期不验收。后续（不在本期）：交易类型中文映射、地址标签、回补操作台、DEX 只读 API、角色与权限配置。

不做 说明
登录页 不交付登录/登出；身份来自已有内部会话
角色与权限 不交付成员菜单授权、角色切换、权限配置页
独立查询菜单 区块/交易/地址/数据检查/交易类型/提议者不是侧栏模块；区块核对只走顶栏
告警关联交易 无「查看关联数据」；不打开交易/地址作为告警关联对象
改回告警中 已处理不可改回告警中
自动恢复状态 无「已恢复」；巡检不因三项均通过而改告警状态
修复动作 无补齐、重处理、回补、分派
操作记录页 备注与处理成功即可，不提供审计查询页
交易运营 / EVM 订单、仓位、Vault、合约、Token、NFT、Gas
